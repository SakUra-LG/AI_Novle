# 《流行天王重生》生成架构与 v13 审查报告

## 1. 当前权威数据流

```text
global_story_outline_v5_qwen_500.json
  ├─ 人物/实体注册表、年代技术矩阵、因果主链、伏笔
  └─ event_clusters_v2.json（250 个事件簇，每簇 2 章）
       └─ pop_king_plan_compiler.py
            ├─ master_ctx_cards_v2.json（500 张章卡）
            └─ chapter_synopses_v5_qwen_500.json（500 章梗概）
                 └─ generate_pop_king_body_v5.py
                      ├─ 规划指纹与 Neo4j PlotCluster
                      ├─ 最近 20 章正文 + StoryMemory
                      ├─ 两章联合生成
                      ├─ 确定性校验 + 严格语义审稿
                      └─ chapters / provenance / audit / StoryMemory 提交
```

权威顺序是“总纲 → 事件簇 → 编译章卡/梗概 → 正文”。总纲或事件簇变化后必须重建规划指纹、PlotCluster 和正文记忆，不能沿用旧 story_id 冒充兼容。

## 4. 生成器针对性修改

- 第 2 章身份契约允许 11 岁未成年，不再与“成年男性”提示冲突；后续按章卡 life_stage 切换。
- 年龄按生日精确计算，并对历史回忆/法律条款作语义豁免。
- 首章不泄漏两章事件的预设结局、代价与解除方式。
- 最近正文比较窗口从 5 章扩到 20 章；风格提示窗口扩到 10 章，并动态提取高频 4–8 字片段。
- 新增结算签名、死亡链、代价持续、缺陷反对者、文书权限的生成前硬门禁。
- 两章联合验收不再把“缺少状态转移/结算”降级为可放行 warning。
- 语义审稿 schema 严格要求 `ok` 为布尔值、`evidence` 为字符串数组；畸形 JSON 不再误通过。
- `continuity_rejected` 的候选不得写入断点或记忆。
- 角色状态改为由章卡编译的 lifecycle、active_costs、state transitions、artifact permissions，而非自由摘要。
- 移除无效的 `system_prompt.replace()` 补丁，规则直接进入系统提示词。
