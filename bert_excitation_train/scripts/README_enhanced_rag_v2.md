# 增强版RAG生成器 v2.0 使用说明

## 📋 功能概述

本脚本是专门为**重生复仇类小说**设计的章节生成器，具有以下核心功能：

1. **自动加载章节梗概**：从 `outputs/master_ctx.txt` 自动读取对应章节的梗概
2. **自动加载上一世线索**：从 `outputs/prev_life_ctx.txt` 自动读取对应章节的上一世记忆线索
3. **自动加载上一章正文**：自动查找并加载上一章正文，确保情节自然衔接
4. **高情绪强度生成**：优先检索高分高情绪样本，确保生成内容情绪强度达标
5. **智能上下文管理**：只加载上一章正文（而非所有章节），避免上下文过长导致模型崩溃

## 🎯 设计理念

### 为什么只加载上一章正文？

1. **避免上下文过长**：如果加载所有已生成章节，上下文会非常长，可能导致：
   - 模型token限制超限
   - 生成速度变慢
   - 成本增加

2. **章节梗概保证整体一致性**：
   - 章节梗概文件（`master_ctx.txt`）包含了整个小说的故事线
   - 只要严格按照章节梗概生成，整体情节不会跳脱
   - 章节梗概是结构化的，长度可控（约100行）

3. **上一章正文保证局部衔接**：
   - 上一章结尾和本章开头的衔接最关键
   - 只加载上一章正文（最后500字或最后一段），既能保证衔接，又不会过长

## 📁 文件结构要求

### 必须存在的文件

1. **章节梗概文件**：`outputs/master_ctx.txt`
   - 格式：`第X章 ：标题……：内容描述`
   - 示例：`第1章 ：她被扔在ICU病房的地板上……：她全身插满管子，呼吸机发出尖锐的嗡鸣声。`

2. **上一世线索文件**：`outputs/prev_life_ctx.txt`
   - 格式：`第X章对应线索：线索内容（对应今生第X章）`
   - 示例：`第1章对应线索：她记得在ICU病房的地板上，被推进抢救室时摔得头破血流...`

3. **样本数据文件**：
   - `data/universal_samples_scored.txt`：评分样本
   - `data/universal_samples_vectors.npy`：样本向量
   - `data/universal_samples_data.json`：样本元数据

### 可选文件

- `config/project_configs.json`：项目配置（角色、背景、风格等）
- `outputs/chapters/chapter_XXX.txt`：已生成的章节正文（用于衔接）

## 🚀 使用方法

### 基本命令

```bash
python scripts/enhanced_rag_generator_v2.py --chapter 1
```

### 完整参数

```bash
python scripts/enhanced_rag_generator_v2.py \
  --project "暗河噬城" \
  --chapter 1 \
  --prompt "请重点突出重生后的冷静和预判" \
  --versions 3 \
  --min_score 70 \
  --min_emotion 0.6
```

### 参数说明

- `--project`：项目名称（默认："暗河噬城"）
- `--chapter`：**必须**，章节编号（如：1, 2, 3...）
- `--prompt`：可选，额外生成提示（章节梗概和上一世线索会自动加载）
- `--versions`：生成版本数（默认：3）
- `--min_score`：最低样本评分（默认：70）
- `--min_emotion`：最低情绪强度要求（默认：0.6）

## 📝 生成流程

```
1. 加载章节梗概（master_ctx.txt）
   ↓
2. 加载上一世线索（prev_life_ctx.txt）
   ↓
3. 查找上一章正文（outputs/chapters/chapter_XXX.txt）
   ↓
4. 加载高分高情绪样本
   ↓
5. 检索相关样本
   ↓
6. 构建增强提示词（包含所有上下文）
   ↓
7. 生成多个版本
   ↓
8. 保存结果到 outputs/ch{chapter}_enhanced_rag_{timestamp}.txt
   ↓
9. 保存最佳版本到 outputs/chapters/chapter_{chapter:03d}.txt
```

## 📊 输出文件

### 1. 完整结果文件

**路径**：`outputs/ch{chapter}_enhanced_rag_{timestamp}.txt`

**内容**：
- 元数据（项目、章节、生成时间等）
- 所有版本的生成内容
- 使用的样本信息

### 2. 最佳版本文件（用于后续章节加载）

**路径**：`outputs/chapters/chapter_{chapter:03d}.txt`

**内容**：
- 纯正文内容（已移除元数据）
- 用于下一章生成时的衔接上下文

## 🔍 上一章正文查找逻辑

脚本会按以下顺序查找上一章正文：

1. `outputs/chapters/chapter_{prev_chapter:03d}.txt`
2. `data/chapters/chapter_{prev_chapter:03d}.txt`
3. `data/generated/{project_name}/ch{prev_chapter}_v*.txt`
4. `outputs/ch{prev_chapter}_*.txt`

**优先选择最新的文件**。

## ⚠️ 注意事项

1. **章节编号必须连续**：如果跳过某些章节，脚本可能找不到上一章正文
2. **文件格式必须正确**：章节梗概和上一世线索文件必须符合指定格式
3. **首次生成**：如果生成第1章，不会加载上一章正文（这是正常的）
4. **章节范围**：如果章节梗概中使用范围格式（如"第11-15章"），脚本会自动识别

## 💡 使用建议

1. **按顺序生成**：建议按章节顺序（1, 2, 3...）生成，确保每章都能找到上一章
2. **检查生成结果**：生成后检查 `outputs/chapters/chapter_XXX.txt` 文件，确保内容正确
3. **调整参数**：如果生成质量不理想，可以调整 `--min_score` 和 `--min_emotion` 参数
4. **添加额外提示**：如果需要强调某些方面，可以使用 `--prompt` 参数

## 🔧 技术细节

### 上下文长度控制

- **章节梗概全文**：约100行，结构化，长度可控
- **上一世线索全文**：约100行，结构化，长度可控
- **上一章正文**：只取最后500字或最后一段，避免过长

### 样本检索策略

1. **高分样本优先**：评分 >= min_score，情绪强度 >= min_emotion
2. **语义相似度**：基于章节梗概和上一世线索进行语义检索
3. **综合评分**：评分权重0.4 + 情绪强度权重0.4 + 重叠度权重0.2

## 📞 问题排查

### 问题1：找不到章节梗概

**错误信息**：`⚠️ 未找到第X章的梗概`

**解决方法**：
- 检查 `outputs/master_ctx.txt` 文件是否存在
- 检查文件格式是否正确（`第X章 ：标题……：内容`）
- 检查章节编号是否匹配

### 问题2：找不到上一世线索

**错误信息**：`⚠️ 未找到第X章的上一世线索`

**解决方法**：
- 检查 `outputs/prev_life_ctx.txt` 文件是否存在
- 检查文件格式是否正确（`第X章对应线索：线索内容`）
- 检查章节编号是否匹配

### 问题3：找不到上一章正文

**错误信息**：`⚠️ 未找到第X章的正文文件`

**解决方法**：
- 检查是否已生成上一章
- 检查上一章文件是否保存在正确位置
- 检查文件名格式是否正确

### 问题4：生成内容不符合预期

**解决方法**：
- 检查章节梗概和上一世线索是否正确
- 调整 `--min_score` 和 `--min_emotion` 参数
- 使用 `--prompt` 添加更具体的生成要求
