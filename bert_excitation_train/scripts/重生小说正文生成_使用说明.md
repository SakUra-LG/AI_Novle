# 重生小说正文生成器 — 使用说明

本文档说明如何使用 `generate_chapter_content.py` 按章节生成重生复仇小说正文。

---

## 一、脚本简介

`generate_chapter_content.py` 是一个**重生复仇小说正文生成器**，主要功能包括：

- **按章节生成**：根据章节梗概和上一世线索，生成单章正文（约 800–1200 字）
- **RAG 样本检索**：从通用样本库中检索相似片段，作为风格与情节参考
- **循环评分与优化**：对生成内容做规则评分和情绪分析，未达标时自动迭代优化
- **回忆触发规则**：根据人物、地点、事件类型自动判断是否插入「上一世回忆」段落

适合在已有**章节梗概**和**上一世线索**的前提下，逐章生成短剧风格的重生复仇正文。

---

## 二、环境与依赖

- **Python**：建议 3.8+
- **依赖模块**：脚本同目录下会用到  
  `smart_sample_search`、`optimized_rule_scorer`、`emotion_analyzer`，以及 `dashscope`（通义千问 API）
- **API**：需配置通义千问 API Key（脚本内或环境变量，见脚本中的 `API_Key_QW`）

确保在项目根目录（如 `AI_Novle`）或 `bert_excitation_train` 下运行，以便相对路径正确解析。

---

## 三、输入文件准备

### 1. 章节梗概（必需）

- **默认路径**：`bert_excitation_train/outputs/master_ctx.txt`
- **格式**：每行一章，且行内包含「第N章」和冒号，脚本会解析「第N章」后的内容为该章梗概。

示例：

```text
第1章：她被扔在ICU病房的地板上，全身插满管子，呼吸机发出尖锐的嗡鸣声……
第2章：她在病床上睁不开眼睛，却听见无数谩骂的声音，网络直播平台不断弹出……
第3章：她回忆上一世被诬陷的经过，决定先收集证据……
```

- 可用中文冒号 `：` 或英文冒号 `:`，脚本都会识别。

**避免章节重复的梗概写法建议**：若发现生成的第 2 章、第 3 章与前面章节开头或情节雷同，多半是梗概太笼统或两章焦点重叠。建议：
- **每章梗概明确写出「本章独有」的入口与焦点**：例如第 1 章写「ICU 地面、家人冷眼、一句台词」，第 2 章就写「病床上听到的声音、网络弹幕、丈夫在镜头前宣布」，让开篇与核心情节点区分开。
- **不要多章共用同一段梗概**：每章一行梗概，且这一行里要有本章特有的场景或转折（如「网络直播」「镜头下宣布」「氧气面罩堵住」等），便于生成时与前文区分。
- 脚本已支持「前文已出现的情节与场景 - 禁止重复」：生成第 2 章及以后时，会自动把前几章的开头与前半段喂给模型，并要求本章不重复这些内容；配合梗概写清本章焦点，效果更好。

### 2. 上一世线索（强烈推荐）

- **默认路径**：`bert_excitation_train/outputs/prev_life_ctx.txt`
- **格式**：每行一条，且行内包含「第N章对应线索」和冒号，脚本会解析冒号后的内容为该章上一世回忆素材。

示例：

```text
第1章对应线索：她记得在ICU病房的地板上，被推进抢救室时摔得头破血流，无人理会……
第2章对应线索：她回想在病床上听到网上弹幕疯狂刷屏「烂货」「自作孽不可活」……
第3章对应线索：上一世会议上被陈主任当众诬陷数据造假，她拿不出证据只能认栽……
```

- 若该文件不存在，脚本会提示并**跳过**上一世回忆触发，正文仍可生成，但不会自动插入回忆段落。

### 3. 通用样本库（RAG，推荐提前准备）

- **样本文本**：`bert_excitation_train/data/universal_samples.txt`
- **生成的数据与向量**：  
  `bert_excitation_train/data/universal_samples_data.json`  
  `bert_excitation_train/data/universal_samples_vectors.npy`

若你修改了 `universal_samples.txt`，需要先运行样本处理脚本重建向量库，例如：

```powershell
python .\bert_excitation_train\scripts\handle_universal_samples.py
```

未初始化或未更新时，脚本会提示未找到 RAG 样本，但仍可用「基础生成」继续。

## 四、命令行用法

### 基本命令

在项目根目录（如 `AI_Novle`）下执行：

```powershell
python .\bert_excitation_train\scripts\generate_chapter_content.py --chapter 1
```

或先进入 `bert_excitation_train` 再执行：

```powershell
cd .\bert_excitation_train
python .\scripts\generate_chapter_content.py --chapter 1
```

### 参数说明

| 参数 | 含义 | 是否必填 | 默认值 |
|------|------|----------|--------|
| `--chapter` | 要生成的章节号（整数） | **必填** | 无 |
| `--master-ctx` | 章节梗概文件路径 | 否 | `outputs/master_ctx.txt` |
| `--prev-life-ctx` | 上一世线索文件路径 | 否 | `outputs/prev_life_ctx.txt` |
| `--versions` | 每章生成的版本数量 | 否 | 3 |
| `--iterations` | 每个版本的最大情绪优化迭代次数 | 否 | 3 |
| `--min-emotion` | 情绪强度达标阈值（0–1） | 否 | 0.6 |

路径可为相对路径（相对 `bert_excitation_train` 目录）或绝对路径。

### 使用示例

**只生成第 2 章（使用默认梗概与线索路径）：**

```powershell
python .\bert_excitation_train\scripts\generate_chapter_content.py --chapter 2
```

**指定梗概与线索文件路径：**

```powershell
python .\bert_excitation_train\scripts\generate_chapter_content.py --chapter 3 `
  --master-ctx .\bert_excitation_train\outputs\master_ctx.txt `
  --prev-life-ctx .\bert_excitation_train\outputs\prev_life_ctx.txt
```

**提高版本数与迭代次数，并放宽情绪阈值：**

```powershell
python .\bert_excitation_train\scripts\generate_chapter_content.py --chapter 1 `
  --versions 5 --iterations 5 --min-emotion 0.5
```

## 五、输出说明

- **保存位置**：默认在 `bert_excitation_train/outputs/chapters/` 下。
- **文件命名**：`chapter_001.txt`、`chapter_002.txt`、…（按章节号三位数命名）。
- **内容**：当前章节的「最佳版本」正文（综合规则评分与情绪强度选出的版本），纯正文，无标题或说明。
- **跨运行衔接**：脚本会从该目录加载已有章节（默认最近 30 章），用于前文摘要与高分片段参考，保证多章连续生成时的连贯性。

## 六、推荐工作流程（重生小说编写）

1. **撰写大纲与梗概**  
   在 `outputs/master_ctx.txt` 中按「第N章：梗概内容」写好每一章梗概。

2. **撰写上一世线索**  
   在 `outputs/prev_life_ctx.txt` 中按「第N章对应线索：线索内容」写好与各章对应的上一世回忆素材，便于脚本在合适节点插入回忆。

3. **（可选）准备/更新 RAG 样本**  
   编辑 `data/universal_samples.txt`，需要时运行 `handle_universal_samples.py` 更新向量库。

4. **按章生成**  
   从第 1 章开始，依次执行（例如 1→2→3…）：
   ```powershell
   python .\bert_excitation_train\scripts\generate_chapter_content.py --chapter 1
   python .\bert_excitation_train\scripts\generate_chapter_content.py --chapter 2
   ...
   ```
   这样每章都能利用前面已生成章节做前文衔接与高分片段参考。

5. **查看与修改**  
   到 `outputs/chapters/` 下查看 `chapter_001.txt`、`chapter_002.txt` 等，按需人工润色或微调。

## 七、常见问题

### 1. 报错：未找到 `master_ctx.txt` 或 `prev_life_ctx.txt`

- **原因**：当前工作目录或相对路径解析导致找不到文件。
- **解决**：  
  - 在项目根目录（如 `AI_Novle`）下按本文档示例命令运行；或  
  - 使用 `--master-ctx`、`--prev-life-ctx` 显式指定绝对路径或相对 `bert_excitation_train` 的正确相对路径。

### 2. 提示「未找到上一世线索文件」

- 脚本会继续运行，但不会插入上一世回忆。若需要回忆段落，请创建并填写 `prev_life_ctx.txt`（或通过 `--prev-life-ctx` 指定你的线索文件）。

### 3. 控制台出现 `UNEXPECTED embeddings.position_ids` 等 BERT/向量相关提示

- 多为模型加载时的提示，若不伴随后续报错，一般可忽略，不影响生成。

### 4. 想一次只生成一个版本或减少 API 调用

- 使用 `--versions 1`，例如：  
  `python ... --chapter 1 --versions 1`

### 5. 生成内容情绪不够强

- 可适当降低阈值：`--min-emotion 0.5`；  
- 或增加迭代次数：`--iterations 5`，让脚本多轮优化情绪表达。

## 八、情绪强度评分规则说明

控制台中的「情绪强度」由 `emotion_analyzer.py` 计算，用于判断生成正文是否达到「情绪足够强」的标准（默认目标 ≥ 0.6）。规则如下。

### 当前计算方式（简述）

1. **若加载了预训练情感模型**（`uer/roberta-base-finetuned-jd-binary-chinese`）  
   - 模型是**二分类**（正/负情感），面向商品评论场景。  
   - **情绪强度 = 最大类别概率 − 次大类别概率**（即「置信度差距」）。  
   - 例如：P(正)=0.6、P(负)=0.4 → 强度 = 0.2；要得到 0.6 需要约 0.8 vs 0.2，即模型必须非常偏向某一类。

2. **若未加载模型（回退到词典）**  
   - 用中文情绪词典统计多维度情绪得分后**做归一化**（各维度之和为 1）。  
   - **情绪强度 = 各维度中最大的那个得分**。  
   - 维度较多（如 9 维）时，单维占比往往只有 0.2～0.4，所以强度也容易偏低。

### 为什么经常偏低？

- **任务不匹配**：脚本期望的「情绪强度」是「正文里情绪写得有多浓」，而当前实现更接近「分类置信度」或「归一化后单一情绪占比」，小说正文常带混合、含蓄情绪，置信度或单维占比自然不高。  
- **二分类 + 评论模型**：叙事文本与评论分布不同，模型常给出 0.55 vs 0.45 这类接近的结果，强度只有 0.1；即便文中情绪很浓，数值仍可能卡在 0.3～0.5。  
- **归一化**：词典回退时各情绪加和为 1，主导情绪占比被摊薄，难以冲高到 0.6。

### 使用建议

- **临时**：若生成质量已满意，可把达标线调低，例如 `--min-emotion 0.35` 或 `--min-emotion 0.4`，避免因数值长期不达标而反复优化。  
- **长期**：脚本已采用**复合情绪强度**（在 `emotion_analyzer.py` 中）：在原有分类置信度基础上，叠加**情绪词密度**、**情绪深度**、**转折强度**，使叙事文在情绪词足够、有层次时更容易达到 0.6。若仍长期偏低，可再调低 `--min-emotion` 或检查正文是否缺少直接情绪词（如愤怒、恐惧、紧张等）。

## 九、技术要点简述（供参考）

- **回忆触发**：当章节梗概或线索中出现已抽取的**人物**、**地点**或**事件类型**（如陷害、嘲讽、会议、羞辱等）时，会触发「上一世回忆」插入逻辑。
- **评分与选优**：每章会生成多个版本，经规则评分与情绪分析后，取综合得分最高的版本写入 `chapter_XXX.txt`。
- **前文利用**：会加载已生成章节的前文摘要及高评分片段，用于提示模型保持风格与情节连贯。

情绪强度实现细节见 `emotion_analyzer.py`（`analyze()` 及复合强度计算）。
